# Публикация RAID GAME 0.6

15 октября 2026 обновление **опубликовано на https://raid-game.ru** по прямому поручению пользователя. Активная сборка `0.6.0-68aef700d59bc522`, контент `reid-online-060-schema3-frontier16-scav-items-quests32`. Сервис `raid-game` активен; `storageReady: true`, `draining: false`, `admissionClosed: false`. При переключении активных рейдов и необработанных результатов не было.

Релиз: `/opt/raid-game/releases/raid-game-0.6.0-frontier-20261015`; ссылка `/opt/raid-game/current` переключена штатным `deploy/release.sh`. Время ожидания завершения рейдов в скрипте увеличено до 55 минут с учётом новых 50-минутных локаций. Старые релизы не перезаписаны.

**PASSED:** финальный локальный `npm run verify` — 467/467; физический обход — 4175/4175; на VPS 16 целевых тестов и минутный прогон с пятью клиентами (пиковый p95 14.84 мс, RSS 395 МиБ). Проверка ближайших навигационных узлов прошла на всех пяти картах локально и в финальном VPS-прогоне. Первоначальный параллельный запуск был прерван из-за давления на память; после удаления временных загрузочных архивов повторный набор прошёл полностью. Проверки не утверждают устойчивость нескольких одновременных отрядов на VPS с 2 ГиБ RAM.

**PASSED с VPS:** публичный HTTPS и HSTS, HTML и три JS/CSS-ресурса, SHA-256 всех девяти новых текстур, вход, чтение профиля, WSS HELLO, выход. Создана только временная приёмочная учётная запись; после проверки она и её сессии удалены. Два существовавших аккаунта не изменялись. После приёмки снят файл блокировки входа в рейды. В журнале сервиса ошибок запуска нет.

**BLOCKED с Mac:** публичный HTTPS завершается сетевым тайм-аутом. Поэтому прохождение через внешнюю сеть и кооператив с нескольких внешних браузеров **NOT RUN**. Локальный браузер подтвердил загрузку собранного React-клиента и игрового рендерера; встроенный браузер ограничил ручное прохождение захватом мыши. Подробности: [TEST_REPORT_0.6_RU.md](TEST_REPORT_0.6_RU.md).

## Сохранения и откат

Перед переключением сервер остановлен, SQLite скопирована штатным backup API и проверена на целостность. Резервная копия: `/var/backups/raid-game/raid-game-20261015T070040Z.sqlite` (имя по часам VPS). Её локальная копия прошла integrity_check и совпала по SHA-256 (`2bb037703dd6bd99a0db680c0c1d01f1f12ff0da85182d6dab93e530bb45a1c5`). Закрытая локальная копия находится в пользовательском каталоге конфигурации RAID GAME, вне проекта и архива. Проверены оба профиля схемы 3; preflight на отдельной копии подтвердил регистрацию, чтение профиля и WebSocket. Схема БД и сохранений не менялась; прогресс не сбрасывался.

Совместимый откат: `/opt/raid-game/releases/raid-game-051-rollback-060-compatible`. Это отдельная копия предыдущего 0.5.1: валидатор принимает и сохраняет записи `quest_23`–`quest_32`, а старый интерфейс не предлагает эти задания на прежних картах. Проверена сборка, native SQLite, совместимость двух действующих профилей и фикстура с десятью новыми заданиями. Исторический 0.5.1 не изменён.

При необходимости отката оператор запускает текущий скрипт `deploy/release.sh` с путём совместимого отката, ждёт завершения рейдов, проверяет новую резервную копию, health, вход и WebSocket и затем снимает `/var/lib/raid-game/admission.closed`. **Нельзя возвращать старую SQLite поверх нового прогресса.** Прямое переключение на исходный исторический 0.5.1 после принятия новых заданий несовместимо с их ID.

Журналы без учётных данных: `artifacts/060/deploy.log`, `production-acceptance.json`, `vps-soak.json`, `vps-tests.log`. Отдельный архив в `Versions/` не создавался; исходники и обе сборки находятся в рабочем проекте и каталоге релиза на VPS.
