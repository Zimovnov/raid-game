# РЕЙД — продолжение исходной сборки

**Начните с START_HERE_RU.md.** Здесь находятся реальный исходный проект, готовый `dist`, локальный сервер и тесты. Сборка 0.2.0 продолжает присланную 0.1, а не заменяет её отдельной демонстрацией.

Полное задание в `docs/ORIGINAL_SPEC_RU.md` ещё не закрыто. Основные незавершённые направления — реальная браузерная и интернет-приёмка, полная детализация пяти карт, точные брендовые кандидаты модулей, расширенная модель инвентаря и анимационная полировка. Количество записей каталога не означает выполнение всего ТЗ.

## Быстрый запуск готовой игры

Требуется Node.js 22.12 или новее; фактически проверен Node.js 22.16.0. Windows: `START_WINDOWS.cmd`; macOS: `START_MAC.command`; Linux: `bash START_LINUX.sh`. Альтернатива в Терминале из папки проекта:

```bash
node tools/serve.mjs --open
```

Если скрипт macOS не имеет execute-разрешения, достаточно воспользоваться этой командой. При необходимости разрешение даётся только самому файлу: `chmod u+x START_MAC.command`; отключать системную безопасность не требуется.

Адрес сервера обычно `http://localhost:8080`. Используйте адрес из вывода, если выбран другой порт. Терминал должен оставаться открытым. Ctrl+C завершает сервер. Готовая сборка не требует npm-загрузок. Открытие `dist/index.html` через `file://` не поддерживается.

## Магазины и оружейная

«Зарядить»/«Разрядить» в схроне доступны оружию со съёмным магазином и отдельным магазинам. В рейде R меняет заряженный запасной магазин; Tab → выбор магазина → «Зарядить» позволяет перекладывать подходящие патроны по одному. Установленный магазин тоже можно дозарядить через этот экран. Внутренняя/трубчатая подача использует пошаговую зарядку R. Отдельного патрона в патроннике пока нет.

Снятый магазин сохраняет ID, состояние и боезапас. Продажа и масса учитывают патроны один раз. Покупка оружия не выдаёт бесплатный полный магазин. Предпросмотр пресета не тратит деньги. «Из своих деталей» не докупает отсутствующее; «Купить недостающее» выполняет покупку и сборку атомарно. Удаление родителя переносит снятые дочерние элементы в схрон либо отменяет всю операцию при нехватке места.

12 пресетов показаны для подходящей оружейной основы, а не одновременно для любой пушки. Импорт/экспорт своих пресетов остаётся ограниченным JSON. В тир можно перейти после применения сборки.

## Кооператив: запуск и границы

Игровой транспорт — настоящий нативный WebRTC DataChannel. Хозяин выполняет симуляцию; второй игрок отправляет ввод/действия. WebSocket используется только для сигнализации. В коде есть общий старт после готовности и загрузки, одна добыча на двоих, раздельные результаты, переподключение живой гостевой вкладки, ограничения размера/частоты пакетов и диагностические ошибки. Добавлены отбрасывание устаревших ICE/ANSWER, ограничение очереди кандидатов, проверка метки канала и сообщение об отсутствии ICE-кандидатов.

Основной сценарий: оба открывают одну опубликованную сборку; хозяин создаёт отряд, друг открывает приглашение, оба готовы, хозяин запускает рейд. **Сборка пока не опубликована.** Для локальных копий на двух компьютерах оставьте «Общий PeerServer» у обоих и передайте код из игры, а не ссылку на localhost.

`public/network-config.json` содержит публичный адрес сигнализации и список ICE-серверов. Закрытые мастер-ключи TURN туда помещать нельзя: файл доступен клиенту. Собственный relay не развёрнут. Общий PeerServer — внешняя зависимость; его текущая доступность и прохождение NAT пользователей не подтверждены. Одиночный режим и тир не требуют этой сигнализации.

Для явного теста локальной сигнализации есть `?signal=local`, а сервер слушает `/peerjs`. По умолчанию сервер доступен только на loopback. `node tools/serve.mjs --lan` — отдельный осознанный режим привязки к локальной сети, не обход firewall и не публикация в интернет. LAN/HTTP может не давать все secure-context возможности, поэтому для обычной игры используйте HTTPS-публикацию или локальный localhost.

## Сохранения и аварии

Профиль хранится в IndexedDB, настройки — в localStorage. База сохраняет имя `reid-save-v1`, но версия структуры профиля теперь 2. При чтении схемы 1 сохранение копируется, существующие патроны переносятся в магазин, старый профиль помещается в backups той же транзакцией. Неоднозначные повреждённые данные отклоняются. Полная интеграционная проверка миграции в браузере пока заблокирована; чистая функция миграции протестирована.

Перед рейдом записывается предрейдовый комплект в escrow. Эвакуация выдаёт добычу один раз; полный схрон использует сохраняемый inbox. Смерть и намеренный выход не отменяются повторным результатом. Технический обрыв возвращает только предрейдовый комплект без добычи оборванного рейда. Происхождение локальных вещей не защищено от владельца компьютера; глобальной доверенной экономики и миграции хозяина нет.

Перезагрузка гостевой страницы не эквивалентна восстановлению живого DataChannel: токен сессии не сохраняется для входа после полной перезагрузки. Возврат из краткого обрыва работающей вкладки предусмотрен примерно 60 секунд. Компьютер/вкладку хозяина во время рейда не закрывайте и не отправляйте в сон.

Старый профиль заранее экспортируйте в «Настройках». Профиль привязан к origin, то есть браузеру, протоколу, имени хоста и порту. `localhost:8080`, `127.0.0.1:8080`, `localhost:8081` и публичный домен имеют разные хранилища. Для переноса нужен экспорт/импорт, а не копирование папки игры.

## Разработка и воспроизводимая проверка

```bash
npm ci --offline
npm run verify
npm run dev
```

TypeScript 5.8.3 приложен в `vendor`, lockfile ссылается на локальный tarball. `npm run dev` выполняет одну сборку и запускает сервер; автоматического watch/HMR нет. После правки TypeScript остановите сервер и выполните команду снова. `npm run build` обновляет хеши собственных ассетов, вычисляет хеш контента и создаёт `dist`.

| Команда | Что выполняется |
|---|---|
| `npm run typecheck` | строгая проверка всего src |
| `npm run lint` | TypeScript + AST-проверки, не выдуманный echo-pass |
| `npm test` | сборка и все Node-тесты из tests |
| `npm run test:integration` | протокол-харнесс и реальные HTTP/WebSocket-тесты сервера |
| `npm run validate:content` | сборка, совместимость/геометрия всех деталей, доступность лута/выходов |
| `npm run verify` | typecheck, lint, build, все Node-тесты, content validation |
| `npm run test:ui` | изолированные DOM-шаблоны в Chromium; Python/Playwright |
| `npm run test:e2e` | запуск полной игры в браузере; Python/Playwright |
| `npm run test:rtc` | два Chromium-процесса, настоящий RTC, только сигнализация через тестовый IPC |
| `npm run test:render` | нативный GLES/Mesa рендер настоящих шейдеров/геометрии; Linux + Pillow |
| `npm run test:packaging` | чистая offline-установка, сервер, пробелы/кириллица и занятый порт |

Python-инструменты необязательны для игры и основной Node-проверки. Они используют Python 3, Playwright и, для PNG, Pillow; проверенные версии указаны в `requirements-dev.txt`. Команды выше используют имя `python3`; на Windows можно запускать соответствующий `.py` через `py`. Для браузерных тестов установите Playwright в отдельное окружение и браузер его обычным способом; не меняйте корпоративные политики. `CHROMIUM_PATH` позволяет указать имеющийся исполняемый файл. Нативный GLES-инструмент предназначен для Linux и не является способом запуска самой игры.

Коды проверочных Python-инструментов: 0 — PASS, 1 — FAIL, 2 — BLOCKED. Заблокированный браузерный тест не скрыт внутри успешного `verify` и не считается PASS. Подробный фактический протокол — `TEST_REPORT.md` и `artifacts/`.

## Статическая публикация

`vercel.json` подготовлен для отдельного проекта: Framework Preset — Other, установка `npm ci --offline`, сборка `npm run build`, выход `dist`. Можно загрузить исходники в собственный приватный Git-репозиторий и подключить его к отдельному проекту Vercel. Либо использовать CLI `vercel` из папки проекта после собственной авторизации. Ни аккаунт, ни домены, ни текущие проекты пользователя этой работой не изменялись. Условия хостинга и доступную версию Node уточните в своей панели перед публикацией.

После публикации обязательны отдельная проверка реального URL, создание персонажа, копирование приглашения, подключение второго браузера, рейд, раздельный выход и повторное открытие профиля. Успешная компиляция этого не доказывает. Для обычной игры используйте один постоянный production URL.

## Состав и происхождение

`src/domain` — имущество, магазины, сборки, экономика и миграция; `src/simulation` — движение, бой, боты, укрытия; `src/rendering` — WebGL2 и модельные фабрики; `src/network` — сигнализация/RTC/сессия; `src/content` — оружие, виртуальные модули, лут и карты; `src/persistence` — IndexedDB; `src/ui` и `src/main.ts` — интерфейс и управление.

Существующий нативный движок сохранён: проект не переведён на Three.js/Rapier/Vite. Внешние графические ассеты и актёрские записи не добавлялись. Код собственных моделей/эффектов распространяется по LICENSE; TypeScript содержит свою лицензию в vendor-пакете. Пользовательский ТЗ и справочные названия не являются общей лицензией на чужие бренды. Файлов шрифтов в архиве нет.

Старые отчёты оставлены в `docs/legacy-0.1` исключительно как история. Текущие количества и состояния — в корневых отчётах и `docs/CONTENT_STATUS.json`.
