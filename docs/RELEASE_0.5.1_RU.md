# RAID GAME 0.5.1 — объединённый полевой комплект

Обновление материалов оружия: АК-74М и модифицированный АКМ получили текстурированные GLB/PBR-модели на существующей геометрии; штатный АКМ продолжает использовать детализированную AKMN. URL AKMN теперь меняется вместе с содержимым, чтобы браузер не показывал прежний кеш. Glock проверен: опубликованная модель уже содержит исходный новый атлас. Публикация и границы проверки: [ONLINE_MIGRATION_STATUS_RU.md](ONLINE_MIGRATION_STATUS_RU.md) и [TEST_REPORT_0.5.1_RU.md](TEST_REPORT_0.5.1_RU.md).

Обновление сайта после исходного выпуска: плашка об обязательном cookie сессии, страница `/privacy.html`, защитные HTTP-заголовки и проверка хранения данных. Отчёт: [SECURITY_PRIVACY_0.5.1_RU.md](SECURITY_PRIVACY_0.5.1_RU.md).

Обновление стартовой загрузки: ожидание `/api/me` и игровых модулей ограничено по времени. При недоступности API или JavaScript игрок видит сообщение об ошибке и кнопку повтора вместо бесконечной «Загрузки игры…». Онлайн-вход, офлайн-режим и схема профиля сохранены. Результаты публикации и ограничения проверки: [ONLINE_MIGRATION_STATUS_RU.md](ONLINE_MIGRATION_STATUS_RU.md).

Объединены исходная 0.4, поставка 0.5 и рабочая версия с React/Babylon.js и выделенным сервером. Входные ZIP и исторические каталоги сохранены. Перед работой сделана отдельная резервная копия проекта.

## Что получает игрок

- 36 оружий, 202 модуля, 24 готовые сборки, 23 предмета защиты и 22 задания. Добавлены 9×39 и 7,62×51, новые помещения и ориентиры пяти карт.
- Чёрно-белый интерфейс сохранён. Гардероб использует ту же навигацию и показывает одежду в цвете; лицо и одежду можно бесплатно сохранить без смены имени, фракции, денег, имущества и заданий.
- В каталоге доступно бесплатное испытание любого оружия в тире. Временное снаряжение изолировано от профиля, покупок и наград.
- Сохранён серверный отряд до пяти человек, серверная симуляция, повторное подключение, резервирование снаряжения и однократное применение результата. Шестой участник не допускается.
- Новые GLB/PBR для всех 16 добавленных платформ и их модулей, отдельные детали анимации, UV и дистанционные LOD. Сборка следует существующему дереву предметов. Позы разных экземпляров независимы.
- Готовый Glock подключён к игре с исходными атласами; анимационная копия отделена от оригинала. AKMN и его исходные текстуры сохранены. Одежда и рукава используют 20 оригинальных процедурных тканей и рисунков.

Полный список контента поставки: [арсенал](ARSENAL_GUIDE_0.5_RU.md), [карты](MAP_GUIDE_0.5_RU.md). Исторические заявления о двухместном кооперативе в документах поставки относятся к архиву 0.5, а не к объединённому серверному выпуску.

## Исправления

Перенесены исправления поглощения урона и износа защиты, категорий добычи, лестниц, ограждений, гаражного прохода и посещения POI на правильном этаже. Существующие идентификаторы контейнеров, выходы и пять серверных стартов сохранены.

Дополнительно исправлено соединение навигационных узлов через промежутки между приподнятыми поверхностями: проверяется опора под маршрутом. Исправлено наследование точек крепления Glock и контакт рук с его готовой моделью. Навесные детали на помповом цевье движутся вместе с ним. Текстуры вывесок освобождаются при смене карты. URL новых моделей и тканей содержат хеш содержимого.

## Профили и совместимость

Схема профиля остаётся **3**. `Character.appearance` необязателен; старые профили получают визуальные значения по фракции и прежней одежде. Серверная команда `save-appearance` использует общую доменную валидацию, `expectedRevision` и `operationId`. Изменение в отряде и активном рейде запрещено; повтор операции не создаёт повторных изменений. Чужие поля команды не могут подменять имя, фракцию, деньги или прогресс.

Клиент и сервер проверяют build/content версии. После выпуска нужно обновить открытую вкладку. Возврат к коду 0.4 после появления новых предметов недопустим: откат требует совместимого кода. Нельзя восстанавливать старую базу поверх нового прогресса.

## Запуск и сборка

Node.js **>=22.12**, npm по включённому `package-lock.json`:

```sh
npm ci
npm run verify
npm run serve:online
```

Открыть `http://127.0.0.1:8081/`. Локальная база по умолчанию — `.data/raid-game.sqlite`. Для независимого теста задайте `RAID_DATA_DIR` на отдельный каталог. `npm run dev` запускает Vite с прокси к локальному серверу. `npm run serve:offline` запускает автономную историческую сборку `dist`; основной React-клиент и сервер используют `dist-web`.

Обе сборки включаются в выпуск. Секреты, рабочие базы, `node_modules`, фотографии-референсы и файлы шрифтов в архив не включаются. Исходники новых ассетов и инструкции: [FieldKit051](../art/FieldKit051/README.md); происхождение: [ASSET_CREDITS](ASSET_CREDITS.md).

## Выпуск на VPS

Данные и конфигурация остаются в `/var/lib/raid-game` и `/etc/raid-game`. `deploy/release.sh` закрывает новые рейды, ждёт активные, останавливает записи, делает SQLite backup, проверяет целостность и совместимость профилей, запускает проверку на отдельной копии базы и переключает каталог выпуска. До финальной проверки действует `admission.closed`: вход разрешён, регистрация и изменения экономики закрыты.

При ошибке до открытия экономики возвращается предыдущий код без восстановления старой базы. После открытия допуска требуется совместимый код отката. Команды резервирования и проверки включены в `tools/backup-db.mjs`, `tools/check-db-compat.mjs`, `tools/preflight-server.mjs`.

Фактические результаты и ограничения приёмки: [TEST_REPORT](../TEST_REPORT.md). Этот документ описывает реализацию; он сам по себе не подтверждает публикацию или прохождение всех проверок.
