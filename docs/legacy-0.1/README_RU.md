# РЕЙД — браузерный extraction-шутер, сборка 0.1

В архиве исходники, готовая папка `dist`, локальный сервер и тесты. Это реализованный игровой срез, **не завершение полного ТЗ**. Реальные WebRTC/сохранения/3D-функции написаны, но полная браузерная приёмка и соединение двух физических устройств в этой среде не выполнены. Границы проверки: `TEST_REPORT.md` и `KNOWN_LIMITATIONS.md`.

## Самый простой запуск

Нужен **Node.js 22.12 или новее**. Проверенная здесь версия — 22.16.0. Установщик: https://nodejs.org/en/download . Для игры используйте настольный Chrome или Edge с WebGL2, клавиатурой и мышью. Node нужен только тому, кто запускает локальную копию, не гостю опубликованного сайта.

1. Распакуйте **весь** архив. Откройте папку `reid`, где лежат `package.json`, `dist` и `START_MAC.command`.
2. На Mac запустите `START_MAC.command`, на Windows — `START_WINDOWS.cmd`.
3. Если Mac не запускает `.command`, откройте Терминал в этой папке и выполните:

```bash
node tools/serve.mjs --open
```

Сервер напечатает адрес, обычно `http://localhost:8080`, и попробует открыть браузер. Если порт занят, выберет следующий. Откройте **именно напечатанный адрес**. Окно терминала оставьте открытым; остановка сервера — `Ctrl+C`.

Готовая сборка **не требует `npm install`, API-ключей, аккаунта или скачивания моделей**. Не открывайте `dist/index.html` двойным щелчком через `file://`. Не отключайте Gatekeeper, защиту браузера или брандмауэр ради запуска. Альтернатива `.command` — команда выше; разрешение на исполнение скрипта при необходимости: `chmod +x START_MAC.command`.

## Первый рейд

Создайте персонажа: позывной, BEAR/USEC, лицо и одежда. Первичная выдача — 50 000 игровых рублей, основное оружие, ПМ, запасной АКМ, патроны, медицина и лёгкая броня.

Откройте **«Оружейная»**. Слева выберите оружие и слот; справа — совместимую деталь. Модель меняется сразу в предпросмотре. **«Применить»** сохраняет сборку и покупает отсутствующие модули за показанную цену. Вращайте оружие мышью, приближайте колесом. Нажмите «В тир», чтобы проверить **применённую** сборку без расхода профиля. Неприменённые изменения сначала сохраните или отмените.

Вернитесь в **«Схрон»**. Выделите предмет и переносите кнопками либо перетаскиванием между контейнерами. Сетка упаковывается автоматически, это не свободное ручное размещение в каждой клетке. Для продажи экипированную вещь сначала перенесите в схрон. Купленные патроны также нужно переложить в рюкзак; перезарядка берёт оттуда только подходящий калибр.

Откройте **«В рейд»**, выберите **«Пельменный завод Буянова»** и одиночный рейд. После загрузки нажмите **«Вернуться в игру»**: это захватывает мышь. Ищите вещи на столах/в контейнерах, наведитесь на них с близкого расстояния и нажмите `F`. В открывшемся списке нажмите «Забрать». `M` показывает карту: зелёные круги — выходы. Доберитесь до одного и оставайтесь в его зоне **8 секунд**. Уход из зоны сбрасывает отсчёт.

После эвакуации новая добыча из рюкзака отправится в схрон, а при нехватке места — в сохраняемый приёмник добычи. Продайте вещи торговцу, купите новую деталь и отправляйтесь снова. `Escape` **не** останавливает симуляцию и **не** означает эвакуацию. Намеренное «Покинуть рейд» теряет взятые вещи.

## Управление по умолчанию

| Действие | Клавиша |
|---|---|
| Движение / обзор | WASD / мышь |
| Огонь / прицеливание | ЛКМ / ПКМ |
| Перезарядка | R |
| Взаимодействие | F |
| Бег / приседание / прыжок | Shift / Ctrl / Space |
| Инвентарь / карта | Tab / M |
| Основное / второе оружие | 1 / 2 |
| Аптечка / бинт / еда или вода | 4 / 5 / 6 |
| Фонарь / лазер | L / K; требуется установленный модуль |
| Освободить мышь / меню | Escape |

В настройках можно поменять привязки, чувствительность, FOV, громкость, качание камеры и качество. Голоса по умолчанию выключены: это опциональный системный русский TTS, не запись актёров и не позиционный звук. При отсутствии такого голоса остаются субтитры; звуки боя не зависят от TTS.

## Игра с другом

**Статус:** настоящий WebRTC DataChannel реализован. Сетевые оболочки и локальная сигнализация протестированы; реальное соединение двух браузеров/устройств через WebRTC здесь **не проверено**. В разных сетях может потребоваться TURN. Ни код, ни бесплатная сигнализация не гарантируют соединения любых двух роутеров.

### Через опубликованный сайт

Оба открывают **один и тот же production-адрес одной сборки** и создают своих локальных персонажей. Каждый сначала подготавливает экипировку. Хозяин открывает «Отряд» → оставляет «Общий PeerServer» → «Создать отряд» → копирует приглашение. Друг открывает ссылку или вставляет полный код и нажимает «Подключиться». Код длинный намеренно: содержит случайный идентификатор и секрет приглашения.

Дождитесь двух участников и установленного канала. Хозяин выбирает карту и огонь по своим; изменение этих настроек снимает готовность. Оба нажимают **«Я готов»**, затем хозяин — **«Начать общий рейд»**. Старт ждёт подтверждения загрузки обоих. Каждый эвакуируется отдельно. Не закрывайте и не усыпляйте компьютер хозяина.

### До публикации: две локальные копии

Можно запустить **одинаковый архив на двух компьютерах**, оставить у обоих «Общий PeerServer» и обменяться **кодом**, а не ссылкой на `localhost`. Это тот же WebRTC-путь; оба компьютера должны иметь доступ к внешней сигнализации. Этот вариант тоже требует реальной проверки ваших сетей. Другу в этом сценарии нужен Node для своей локальной копии.

### Локальный технический тест без внешней сигнализации

На одном компьютере откройте два **разных профиля браузера**, например обычное и отдельное приватное окно, по адресу `http://localhost:8080/?signal=local`. Две вкладки одного браузерного профиля блокируются защитой сохранения. Оба контекста должны выбрать встроенную сигнализацию.

Для LAN только по вашему явному решению:

```bash
node tools/serve.mjs --lan
```

Друг использует IP компьютера-хозяина и напечатанный порт с `?signal=local`, например `http://192.168.1.50:8080/?signal=local` (это пример, замените своим адресом). Привязка к LAN не публикует игру в интернете, не пробрасывает порты и не меняет firewall. У HTTP на сетевом IP могут быть ограничения безопасного контекста браузера; для обычной интернет-игры используйте HTTPS-хостинг. LAN на физических устройствах — NOT RUN.

## Публикация на Vercel

Конфигурация подготовлена в `vercel.json`. **Проект ещё не опубликован**. Не используйте уже занятый проект вашего другого сервиса.

Создайте отдельный приватный Git-репозиторий для этой папки и импортируйте его в новый проект Vercel. Параметры: Framework Preset **Other**, корень — папка с `package.json`, Node **22.x или 24.x**, Install Command `npm ci --offline`, Build Command `npm run build`, Output Directory `dist`. Окружение/закрытые ключи не нужны. `vendor/typescript-5.8.3.tgz` обязательно должен попасть в репозиторий.

После Deploy откройте production-URL, проверьте создание персонажа, оружейную, одиночный рейд и подключение друга. Ссылка с `#join=...` открывает ту же страницу; серверного SPA rewrite нет, отсутствующие JS-файлы должны получать 404. На Vercel используйте **общий PeerServer**, не встроенный локальный relay: Node-сервер `tools/serve.mjs` туда не разворачивается. Не обещается бесплатность сервиса при любых объёмах; ограничения аккаунта проверяются в Vercel.

Официальная инструкция: https://vercel.com/docs/deployments . Не делайте исходный репозиторий публичным без своего решения. Проверьте брендовые обозначения перед публичным коммерческим выпуском.

## Сохранения и восстановление

Профиль локальный: браузер + точный origin. `localhost`, другой порт, `127.0.0.1`, staging и production — разные хранилища. В «Настройки» доступны экспорт/импорт профиля. Перед сменой адреса экспортируйте JSON. Импорт проверяет формат и контрольную сумму, перед заменой создаёт резервную запись. Новый персонаж не создаётся поверх старого молча.

При смерти теряется взятая экипировка, но не схрон; защищённый контейнер сохраняется. При техническом обрыве ещё не завершённого рейда возвращается только предрейдовый комплект без найденного лута. Уже применённый финальный результат не отменяется. Это дружеская модель, не защита от читов владельца профиля.

## Изменение исходников и проверки

```bash
npm ci --offline
npm run dev
```

`dev` пересобирает проект и запускает локальный сервер. После изменения исходников остановите сервер `Ctrl+C` и повторите команду; HMR/watch в этом варианте нет. Готовые файлы: `dist/`.

```bash
npm run typecheck
npm run lint
npm test
npm run test:integration
npm run validate:content
npm run verify
```

`verify` проверяет типы, исходники, доменную логику, симуляцию, протокол и контент, **но не является полной браузерной приёмкой**. Для опциональных браузерных тестов нужны Python и Playwright:

```bash
python3 -m pip install -r requirements-dev.txt
python3 -m playwright install chromium
npm run test:ui
npm run test:e2e
```

На Windows используйте установленную команду `python` или `py` вместо `python3`. Если уже установлен совместимый Chromium, путь можно передать через `CHROMIUM_PATH`. E2E создаёт отдельные тестовые контексты, не удаляет основной профиль. Exit 2 означает BLOCKED, а не PASS. Не изменяйте политики безопасности управляемого браузера для обхода запрета.

## Проблемы запуска

«node не найден»: установите Node, закройте и заново откройте терминал. «Нужен WebGL2»: проверьте аппаратное ускорение и поддерживаемый настольный браузер; система явно показывает ошибку, а не рабочую сцену-заглушку. «Профиль открыт в другой вкладке»: закройте дубли этого же origin. «Отряд не найден»: хозяин должен ещё находиться в отряде, код нужно копировать полностью, режим сигнализации должен совпадать. «Версии различаются»: оба используют один архив/одну опубликованную сборку. Проблемы внешней сигнализации не требуют удаления профиля и не должны мешать одиночному режиму.
