# Данные и защита — обновление RAID GAME 0.5.1

Проверена текущая рабочая копия и опубликованный сервер. Плашка сообщает только о необходимом для входа cookie `sid`; это уведомление, а не фиктивное согласие на аналитические cookie. Сведения для игрока доступны по `/privacy.html`.

## Проверенные меры

- Пароли хранятся как salted `scrypt`-хеши, коды восстановления и токены сессий — как хеши; открытые значения в базе не сохраняются.
- Сессия выдаётся cookie `HttpOnly`, `SameSite=Lax`, `Secure` на публичном сервере, со сроком 30 дней. Выход отзывает токен. POST-запросы требуют разрешённый `Origin`, а команды аккаунта — CSRF-токен.
- WebSocket требует действующую сессию, разрешённый `Origin` и совпадающие версии клиента и контента. Сервер считает урон, имущество и результаты рейда. Операции профиля проверяют ревизию и ID для защиты от повторов.
- Node слушает только `127.0.0.1:8081`, внешний HTTPS принимает Caddy. SQLite лежит вне каталогов выпуска: каталог `0700`, база `0600`, владелец `raidgame`. Сервис работает без root с `NoNewPrivileges` и `ProtectSystem=strict`. Резервные копии доступны root и имеют права `0600`.
- Ответы сервера содержат `Referrer-Policy: no-referrer`, запрет встраивания страницы, ограничения `Content-Security-Policy` для встраивания/форм/объектов и запрет доступа к камере, микрофону и геолокации. Публичный HTTPS дополнительно выдаёт HSTS.
- Продакшен-зависимости проверены `npm audit --omit=dev`: критических, высоких, средних и низких известных предупреждений не обнаружено на момент проверки.

## Границы проверки

Это проверка кода, конфигурации и целевые HTTP/WebSocket-тесты, не внешний пентест. Ограничение попыток входа действует в памяти одного процесса и сбрасывается после перезапуска. Сервис самостоятельного удаления аккаунта пока отсутствует; профиль сохраняется для продолжения игры. Реальный вход друзей с двух независимых пользовательских сетей отдельно не подтверждён: локальная сеть Mac ранее давала тайм-аут до публичного сайта, при этом HTTPS с VPS работал. Эти границы не меняют результат пяти локальных WebSocket-клиентов и проверки публичных HTTPS, входа и WebSocket с VPS.

Проверка заголовков и сценариев входа: `tests/security-privacy.test.mjs`. Полный результат `npm run verify`: **441/441 PASSED**. Публичная проверка после переключения подтвердила HTTPS, главную страницу, `/privacy.html`, 17 GLB, вход, профиль, WebSocket, выход и `admissionClosed: false`. С текущего Mac запрос к публичному домену по-прежнему завершается тайм-аутом; это отдельное сетевое ограничение проверки, не успешный тест доступа с этой сети. Рекомендации по заголовкам сверены с [OWASP HTTP Headers Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/HTTP_Headers_Cheat_Sheet.html) и [документацией Caddy](https://caddyserver.com/docs/caddyfile/directives/header).
