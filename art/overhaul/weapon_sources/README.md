# Оригинальные оружейные корпуса RAID GAME

Пакет содержит 33 платформы, по две жёсткие группы `body` и `action` и два LOD. Защищённые AKM, AK-74M, Glock 17 и legacy AKMN не изменяются. Сменные приклады, цевья, рукояти, магазины, оптика и дульные модули производятся отдельно. Внешний интегральный глушитель АС Вал/ВСС входит в неподвижную группу `body`.

Мастер-файлы — `<weaponId>.blend`; воспроизводимый источник геометрии — `tools/art/build_weapon_overhaul.py`. Конфигурация `layout-input.json` экспортирована из действующего `weaponLayout`. Она служит входом производства арта, не новым источником правил игры. Оси авторинга: game X вправо, Y вверх, −Z вперёд; конвертация в Blender применяется один раз. Обе группы экспортируются относительно нулевого weapon root; движение action принадлежит существующему runtime.

Все меши и изображения `weapon-surface-atlas.png` / `weapon-orm-atlas.png` созданы для проекта. Фотографии, логотипы, серийные номера и пиксели из reference set в моделях и текстурах не используются. Сохранённые фотографии остаются в частной внешней папке reference library. Источники визуальных решений и ограничения вариантов записаны в `art/overhaul/briefs/weapons/<weaponId>.md`. Дополнительных сторонних runtime-ассетов и требований атрибуции в этом пакете нет.

Общие атласы 512×512 переиспользуются при авторинге и встроены в каждый самодостаточный GLB. Это не утверждение о дедупликации GPU-текстур между разными GLB: фактический расход памяти и кэширование проверяются в игровом renderer. У каждой группы одна PBR-поверхность с цветом и packed roughness/metallic; фото-текстур и отдельных карт для винтов нет.

Корпуса описывают только внешние поверхности: характерные оболочки, крышки, наружные стволы, прицелы, органы управления, спусковые скобы и доступные снаружи окна. Внутренние механизмы не моделируются. Геометрия соответствует стилизованным размерам существующей игры; это художественные игровые приближения, а не размерные чертежи реального оружия.

## Воспроизведение

Из корня проекта на macOS с Blender:

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background art/overhaul/Blender_Initial_Scene.blend --python-exit-code 1 --python tools/art/build_weapon_overhaul.py -- --no-render
/Applications/Blender.app/Contents/MacOS/Blender --background art/overhaul/Blender_Initial_Scene.blend --python-exit-code 1 --python tools/art/weapon_render_batch.py
python3 tools/art/weapon_qa_report.py
```

Исходная сцена читается и не сохраняется поверх себя. Каждая платформа строится в отдельной временной сцене. `--ids weapon_pm weapon_hk416a5` ограничивает производственный прогон выбранными платформами. Перед производством проверяется `modelingGate: OPEN`.

`<weaponId>-audit.json` содержит фактические UV/normals/triangle checks, повторный импорт и roundtrip, количество полигонов и `groupBounds` в игровых метрах. `production-report.json` объединяет эти данные и дополнительные ограничения LOD, бюджета и muzzle origin. `renders/` содержит четыре контрольных вида каждого корпуса: обе стороны, сверху и 3/4. Файлы в `roundtrip/` — QA-копии; runtime использует только `public/assets/art-overhaul/weapons/`.

## Граница приёмки

Структурный PASS не подтверждает качество полной сборки, IK, ADS, анимацию в браузере, игровые render passes и FPS. Эти проверки требуют подключения отдельных модулей и выполняются владельцем интеграции. Корпуса без модулей намеренно не показывают полный силуэт оружия. Прицельная линия, muzzle и sockets сохраняют действующий контракт; геймплейные значения не меняются ради фотографии.

Проверки публикации, серверов, multiplayer и выпуск архива не входят в данный пакет. Новая версия в `Versions/` не создаётся.
