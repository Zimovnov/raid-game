# Brief: bounds GLB для ground offset выпавшего оружия

## Назначение

При загрузке authored metre-frame модели нижняя точка оружия должна вычисляться по видимым GLB-группам, чтобы выпавшее оружие и инвентарная иконка ложились на пол/preview по фактической форме, включая заменённую модель магазина. Расчёт остаётся в presentation/rendering; симуляция, доменная модель предмета и загрузка GLB не меняются.

## Контракт данных

- Использовать опциональный `ModelAssetDefinition.groupBounds[group]` с локальными `min/max` AABB, рассчитанными по реальным вершинам LOD0 и экспортируемыми Blender-аудитом вместе с манифестом.
- Bounds доступны только для `frame: 'meters'`; legacy normalized GLB продолжают использовать старую нормализованную геометрию и свой прежний fallback.
- Для каждого bounds проверить ровно 3 конечных числа в обоих векторах, `min[axis] <= max[axis]` по всем осям и совпадение group ID с манифестом. Невалидное значение должно отклонять метаданные в валидаторе, а не молча сжиматься/чиниться.
- Не добавлять к исходному корпусу искусственный запас. Bounds для нескольких мешей одной группы должны быть их совокупным локальным LOD0 bounds.

## Преобразование и fallback

Если группа полностью загружена, взять 8 углов локального AABB, провести их через ту же матрицу, что и соответствующая GLB instance (`socket transform` композиция с `groupTransform`, если задан, затем общий loot scale `0.8`) и объединить результат. Нижняя Y координата объединённой видимой сборки задаёт ground offset. Учитывать только `first` binding каждой группы; повторные `Part` для группы не должны повторно расширять bounds.

Оставить `lootModel()` прежним источником procedural fallback bounds. Пересчитывать presentation bounds только в renderer после `ModelAssets.hasGroup(id, group)` подтвердил загрузку требуемой группы/LOD0+LOD1. До готовности, при ошибке GLB, при отсутствии группы или bounds использовать старый результат без асинхронной загрузки в simulation и без изменения shared weapon cache. При смене состояния загрузки надо инвалидировать только renderer-side offset cache по текущей сигнатуре доступности.

Bounds относятся только к видимой части нужной сборки. Загруженная authored группа заменяет её старый primitive; не учитывать спрятанную fallback-геометрию в bounding box. Остальные явно видимые procedural части (например, прицел или отдельная деталь без authored asset) продолжают входить в сборочный bounds.

## Защита данных и проверка

- Не менять geometry/manifest защищённых normalized weapon bodies. Опциональная мета-опись не обязана присутствовать у текущих GLB.
- Проверить невалидные bounds: NaN/Infinity, массив неверной длины, перевёрнутый min/max, неизвестная group, frame кроме meters. Старый manifest без `groupBounds` должен валидироваться как прежде.
- Добавить/сохранить fixture с асимметричным AABB и non-zero socket/group transforms; сравнить ожидаемые экстремумы после 8-угольного преобразования и масштаба `0.8`.
- Проверить три состояния: asset не загружен/ошибка — старый процедурный offset; asset загружен — GLB bounds ложатся на поверхность; availability изменился после загрузки/ошибки — offset cache обновился.
- Проверить отдельную замену/укорачивание магазина: корпус и прочие данные оружия не меняются, а низ/offset меняется только если геометрия нового магазина действительно изменила край сборки.
- Проверить, что `presentationBounds`/offset не мутирует `Part[]`, оружие или inventory item и не участвует в damage, collision, ballistics, loot ownership или серверной симуляции.

Результат этого задания подтверждает только корректность вычисления bounds в renderer и fixture-тестов. Реальное выравнивание целевых моделей требует визуальной проверки каждой GLB в браузере; это не заменяет проверку FPS, инвентарной иконки, тени или игровой сети.
