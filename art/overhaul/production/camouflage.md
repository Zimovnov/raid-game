# Производственный бриф: 49 оригинальных тканевых расцветок

Этот документ и [`camouflage-recipes.json`](camouflage-recipes.json) задают целевой набор, но **не открывают общий art gate и не разрешают генерировать финальные текстуры**. До открытия gate не создавать PNG, материалы или runtime swatches. Сейчас в `src/content/apparel.ts` находятся 20 старых записей; 29 новых ID ниже — утверждённый целевой план, а не уже добавленный или проверенный runtime-контент.

## Объём и границы

Итоговый набор — 49 стабильных ID: все 20 текущих записей плюс 29 новых. JSON — машинно-читаемый каталог полных ID, палитр, долей цвета, физического диапазона пятен и пространственного характера. Сверять его с отдельными briefs в [`art/overhaul/briefs/camouflage/`](../briefs/camouflage/) и `modern-use-evidence.md`; не менять ID по созвучию или предполагаемой актуальности. `cadpat_ar` исключён; для самостоятельного отдельного arid-набора предусмотрен `multicam_arid`, который не заменяет существующий generic `arid`.

## Генерация и физический масштаб

Для каждого ID создать собственную бесшовную квадратную базовую текстуру **1024×1024**. Целевой UV-repeat равен **ровно 0.45 м на сторону** на одежде; следовательно, 1 мм ткани занимает около 2.28 пикселя. Картинка 512×512 — только mip/preview того же тайла, а не второй вариант с физическим repeat 0.45 м. Это сохраняет одинаковый размер пятна на груди, рукаве, бедре, голени, кармане и загнутых складках. Нельзя растянуть конкретную карту отдельно на каждый меш или использовать разный физический масштаб для верхней и нижней формы.

Построитель работает на периодическом (toroidal) поле: точки/контуры, шумовые поля и текстурные мазки должны учитывать копии за границей тайла. Брать периодический шум с целым числом частот по сторонам; при пересечении границы рисовать ту же форму со сдвигами `±1024` по каждой нужной оси. Проверять стык после фильтрации по противоположным полосам и углам, включая градиент/нормаль, если она будет выведена. Не маскировать шов растяжением крайнего ряда пикселей.

Алгоритмы не должны сводиться к общей шумовой карте: `organic` — асимметричные многомасштабные острова с периодическим warp; `digital` — ступенчатые группы пикселей, собранные в нерегулярные поля, с локальными пропусками/слияниями ячеек; `micro-mosaic` — мелкие полигональные группы под широкими цветными массами; `stripe` — изогнутые полосы переменной ширины, расщепляющиеся и затухающие; `leaf` — собственные абстрактные листовые/ветвистые элементы; `splinter` — угловые разнонаправленные осколочные формы; `blurred` — крупные мягкие облака и средние островки; `snow` — большие светлые поля с редкими холодными ветвями/пятнами; `arid` и `tropical` задают отдельную композиционную плотность и гамму. Однотонный класс получает только базовый цвет и низкоамплитудную саржу/ripstop фактуру.

Для каждого camouflage ID детерминировать seed по ID, чтобы производство было воспроизводимым. Панели куртки/брюк получают сдвиг и поворот, производный от asset ID + panel ID, чтобы убрать зеркальные дубли, но не узнаваемую одинаковую композицию через швы. Связать разметку с конкретной категорией материала в wardrobe swatch: одно и то же ID должно давать тот же физический repeat и цветовой баланс на верхе и брюках.

## Материал и оригинальность

Сделать оригинальный игровой base-color print. Поверх него разрешена одна слабая периодическая фактура саржи/ripstop со spacing примерно 0.3–0.8 мм, одинаковая по масштабу между ID; на дальней дистанции она не должна превращаться в шумовой камуфляж. Если текущий материал-контракт поддерживает roughness/normal, выводить их только из авторской фактуры ткани, не добавляя рельефный дубль принта. Тайл непрозрачен.

Одобренные изображения и названия паттернов — research-only. Не трассировать конкретный repeat, не извлекать пиксели из фото/swatch, не оставлять логотипы, маркировки, флаги, эмблемы, скрытые инициалы или подписи. Авторские (`arid`, `tropic`, `winter`, `digital_*`, `multicam_arid` и др.) не переименовывать в реальные штатные расцветки. Для ID с неопределённым текущим применением сохранить оговорку из `modern-use-evidence.md`; технический swatch сам по себе не доказывает службу и не очищает права.

## Приёмка после открытия gate

1. Провалидировать 49 ID, палитры и суммы процентов в `camouflage-recipes.json`; убедиться, что восемь `solid` имеют `spotMm: null` и не получили procedural blots.
2. На исходном 1024 тайле проверить repeat в обеих осях, все четыре угла, native size, 50% mip и bilinear/trilinear фильтрацию. Убедиться, что не возникло шва, шеврона из шума или регулярной сетки.
3. Проверить физические пятна на **торсе/груди, рукаве, штанине и складке**, затем на клапане кармана, манжете, локте и колене. Частота рисунка одинакова; шов не должен случайно выстраивать или зеркалить характерное крупное пятно.
4. Включить каждый ID в настоящем wardrobe swatch игры и проверить как `jacketCamo`, так и `trouserCamo`; осмотреть браузерный runtime крупным планом, целиком и на обычном игровом расстоянии. Проверить фильтрацию/LOD на моаре и мерцание, в стойке, поднятой руке, приседе и сгибе колена. Изолированный tile preview не считается runtime-приёмкой.
5. Отдельно оценить силуэт цвета при обычном игровом расстоянии: крупные семейства читаются, мелкие детали могут естественно смешиваться, но не переливаются. Для solid-цветов фактура видна вблизи и не спорит с силуэтом.
6. В отчёте указывать generation/source seed, исходный 1024 PNG, полученный mip/preview, ID, UV repeat, runtime-кадры и статус прав. Не заявлять браузерную проверку или готовность, пока реальный swatch не выбран и не осмотрен.

Если карта нарушает scale/edge continuity, повторяется рисунок между симметричными панелями, отличается по масштабу верх/низ, теряет семейный силуэт или копирует узнаваемый protected repeat — возвращать конкретный ID на переделку; не принимать весь набор по одному удачному preview.
