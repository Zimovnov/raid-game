# Производственный пакет 01 — 33 модуля AK / Glock

**Назначение:** исполнимый бриф Blender-исполнителю Sol для первой партии модулей. Это инструкция по внешним игровым формам, не производственная/оружейная спецификация. До отдельного открытия общего reference gate файлы не моделировать, не регистрировать в runtime и не заменять защищённые корпуса.

## Что входит и какая геометрия защищена

В пакет включены ровно 33 PASSED ID из `art/overhaul/reference-qa-attachments-ak.json`: 5 AKS-74U, 2 магазина Glock, 19 общих AK-модулей и 7 AK-12-модулей. Каталог и утверждённые формы берутся из `src/content/weapons.ts`, `src/content/weapon-expansion.ts`, `src/content/arsenal-expansion.ts` и соответствующих одноимённых файлов в `art/overhaul/briefs/attachments/`.

Не трогать protected body/action:

- `weapon_akm` и `weapon_ak74m` используют один `/assets/field-kit-051/weapon_ak_common.glb` с сохранёнными `body` и `action`; точный SHA-256 в текущем checkout: `c49567f00e6a80a41a4b0a4b9b679dc9a48f9776fffbdea386cbe23b5ad716d0`.
- `weapon_ak12` использует отдельный `/assets/field-kit-051/weapon_ak12.glb`; SHA-256: `5c582a3587fc5f473d94667a499a0874a48793220cb3c869a0763337ecfaae7a`.
- `weapon_glock17` использует `/assets/field-kit-051/weapon_glock17.glb`; SHA-256: `889823852850a887bbecce6817f0aaed872fb2411cccd0d8f159969f57972286`. Его импортированный GLB уже содержит группу `magazine__glock_17`: интеграция нового магазинного GLB должна выбрать ровно один активный экземпляр установленного магазина, не менять исходный GLB.
- Для AKS-74U в `MODEL_ASSETS` сейчас есть запись `weapon_aks74u` с пустым `groups`; текущая форма корпуса создаётся обычным Part fallback из `additionalWeaponBase('aksu')`. Значит, здесь нет подтверждённого защищённого AKSU GLB/socket: измерять модуль относительно фактической procedural-сборки и `weaponLayout('aksu')`, а в передаче интегратору пометить источник якоря. Не выдавать fallback за GLB.
- AKMN сохранять как отдельный проектный вариант. Путь `AKMN_ASSET_URL`, класс `AKMNAsset` и вызовы из renderer/weapon-animation остаются в коде; фактически `usesAKMNAsset()` сейчас возвращает `false`, поэтому эта условная ветка не включена для текущей сборки. Не перенаправлять на неё модули этой партии и не объявлять ассет удалённым/неиспользуемым только по комментарию в `akmn-asset.ts`.

`MODULE_MODEL_ASSETS` пока пуст. В этой задаче производятся только независимые GLB и этот бриф; изменение registry, suppression встроенных групп и runtime wiring выполняет владелец интеграции после gate. Не менять `MODEL_ASSETS`, существующие body/action, матрицы, анимации, weaponLayout, IK, баллистику, ADS или render passes.

Для AK common default-групп `runtime-review-recipes.json` подтверждает приблизительные envelope `stock ~0.085×0.154×0.328 м`, `handguard ~0.115×0.115×0.28 м`, grip около `0.065×0.19×0.10 м`; это масштабы текущей модельной группы, а не заводские размеры. Фактический mesh bounds и ориентацию импортированного узла проверить в Blender; не использовать матричный envelope как спецификацию внешнего изделия.

### Якоря, требующие отдельного внимания

- AKS-74U `mount` наследует общий стандартный anchor `[0, 0.11, 0]`, а fallback rear sight расположен около `z=+0.08`, `y≈0.12`. Короткий мостик может наехать на целик. Не сдвигать receiver/body. Для первого preview проверить локальную поправку крепления **ΔZ = −0.04 м** (вперёд, к -Z), оставить Y=0.11; принять её только если нижняя площадка полностью опирается на крышку и целик открыт. Если посадка не подтверждается, оставить исходное смещение и передать конфликт владельцу runtime без самовольной правки якоря.
- AK-12 `ak12_cheek` — **полный заменяемый stock-вариант** с высокой щекой, не накладка поверх `ak12_stock`; тот же socket, взаимоисключающий выбор.
- `ak12_guard_long` полностью заменяет `ak12_guard`. Не собирать два цевья друг поверх друга.
- Стандартные AK brake/suppressor и AK-12 brake/can — отдельные варианты одного muzzle slot; не инстансить одновременно. У suppressor должен быть собственный authored outer collar под игровой socket; не переносить заявленную несовместимость/механизм конкретного SKU.
- `ak_cheek` по каталогу — целый stock silhouette с щекой (`stock_cheek`), не child-накладка поверх `ak_stock`.

## Материалы, UV и угловая геометрия

- Палитра согласуется с protected FieldKit: `FK051_metal` / `FK051_polymer` для AK common, тёмный полимер G17 и отдельный металл для Glock magazine пятки/вставки. AK-12 guard/stock получает отдельные крупные полимерные/металлические области. Дерево AK/AKSU — один общий авторский rifle-wood материал с направленным волокном и умеренным сатином. Не копировать цветные logos, маркировки и текстуры с референс-фото.
- На asset — обычно 1 материал, максимум 2, если есть реальная разница материала (полимер/сталь, дерево/металл, резиновый buttpad). Roughness/metallic должны различать сталь, матовый injection-molded polymer, rubber и wood. Не делить одну непрерывную чёрную поверхность на множество материалов.
- Переиспользовать атласы: общий AK polymer, AK blackened metal, rifle wood; Glock polymer + black metal. Целевой максимум 512² на небольшую группу модулей, 1K только на совместный плотный rifle atlas при видимой потребности. Не делать отдельный 2K/4K файл на каждую деталь и не запекать референс-фотографии.
- UVMap обязателен. Читаемые крупные плоскости получают достаточное texel density; швы уводить на нижнюю/внутреннюю грань, wood islands разворачивать вдоль волокна, цилиндры — с одним продольным seam. Никаких нулевых/схлопнутых UV-треугольников; checker/UV test render обязателен.
- Low-poly — крупные устойчивые плоскости с фасками на силуэтных ребрах. Фаска обычно 1–2 мм для небольшого железа, 2–4 мм для stock/guard; измерять в метрах и не размывать профиль. Винты, rail teeth, witness marks и mold lines сокращать до частоты, видимой с FP расстояния; отверстия `ak_vent`, stock frames и magazine windows должны быть реальными открытыми/углублёнными формами там, где silhouette требует, не чёрными наклейками.
- Нормали наружу, без двойных coplanar поверхностей, случайных non-manifold открытых shell ends и чрезмерно тонких перемычек. Сквозные окна stock/guard строить `open_frame`/явными кольцами; простые несущественные отверстия LOD1 можно закрыть, если силуэт не меняется.

## Blender-последовательность для Sol

1. **До открытия проекта:** убедиться, что root открыл общий gate и назначил runtime-владельца. Сверить выбранные 33 ID с перечислением выше и с `reference-qa-attachments-ak.json`; при расхождении остановиться на манифесте, не подменять approved target по памяти.
2. **Сцена:** создать отдельную производственную сцену/копию, защищённые master `.blend`/GLB держать read-only. Подключить копии reference protected base: AK common, AK12, Glock17; AKSU визуально строить на текущей игре/Part fallback, явно пометив provisional fitting. Приватные референсы держать вне runtime export и не паковать в production GLB.
3. **Anchor card:** для каждого ID записать slot, `assetKey`, точку из таблицы, измеренный локальный bounds исходной mesh-группы и выбранный art correction. Поставить wireframe guide размером current anchor. Не совмещать полный asset по bounding-box center и не менять body origin.
4. **Сначала blockout:** один матовый материал, LOD0 silhouette и два ортографических вида (обе стороны), верх/низ и FP camera view. Показать module на неизменённом base с правильным `DEFAULT_BUILDS`/вариантным деревом. Проверить все схожие пары (wood/poly/rail/vent; 20/30/45; AK-12 short/long). Только после silhouette approval детализировать.
5. **Геометрия через `tools/art/blender_meshkit.py`:** использовать `extruded_profile` для stock/cheek/grip/side panels; `open_frame` для AKS wire frame, skeletal openings и guard windows; `loft` с authored одинаковыми rings для изогнутых магазинов и tapered корпусных частей; `hollow_tube` только для видимого внешнего tube-элемента, не как повод делать internals; `bevel` применить с 1 сегментом обычно и 2 только на крупных контурных бликах. Helpers не генерируют целевые силуэты автоматически: все outline/rings задаёт художник по approved brief.
6. **Scale/axes:** координаты деталей задавать относительно socket в метрах; применить `GAME_TO_BLENDER` ровно один раз для перехода game XYZ → Blender Z-up. Экспортировать через `export_asset(..., export_yup=True)`; не добавлять ручной второй поворот Y/Z и не оставлять unapplied negative/parent scale. Проверять -Z forward после roundtrip GLB.
7. **Material/UV pass:** назначить реюзабельные PBR материалы/атласы, раскрыть UVMap, проверить масштаб ткани/дерева/полимера/металла, seams и shading на плоских low-poly facets. Текстуры, если нужны, packed в runtime GLB; reference photos не включать.
8. **LOD pass:** подготовить физически отдельные LOD0 и LOD1 на каждый `assetKey`. LOD1 не просто декор отключает: он сохраняет главную форму stock/guard/магазина/глушителя, reduces rails/ребра/малые фаски/мелкие окна. Проверить переключение при существующем world LOD threshold 12: габарит/пивот не скачет.
9. **Export:** каждый mesh имеет `assetKey` ровно как в таблице и `lod` 0 или 1. `export_asset` принимает только выбранные mesh objects с UV и указанными metadata, требует обе LOD для каждого ключа, экспортирует selection в GLB и не экспортирует animation/camera/lights. Параметры handoff — список ID/group/LOD, общий atlas paths/hashes, source `.blend`, GLB SHA, vertex/triangle counts.
10. **Не анимировать модуль:** все 33 группы rigid. Существующие `action` и bolt motion остаются в protected action group; reload держит текущий authoritative magazine item/capacity. Не добавлять второй rounds counter, кости/skin, новые суставы, сгибание stock или симуляцию крепежа.

## Проверка и критерии приёмки

### До экспорта

- Все 33 ID присутствуют ровно один раз; group key совпадает с таблицей и `src/content/model-assets.ts` naming convention (`stock__`, `handguard__`, `pistolgrip__`, `magazine__`, `mount__`, `muzzle__`). Не вводить новый assetKey/socket.
- Показать каждый модуль отдельно в LOD0/LOD1 и установленным на неизменённую базу. Для collection proof: AKM default wood + 7.62/30; AK-74M default poly + 5.45/30; AK-12 default stock/guard/windowed-30/brake; AKS-74U default + rail/mount; Glock17 с обоими магазинными вариантами.
- Сравнить магазинные длины одновременно: Glock 17 vs 33; 5.45 30 vs 45 vs windowed 30; 7.62 20 vs 30. Точно совпадают вход/горловина; длина и кривизна визуально различаются согласно capacity, а не через масштаб всего объекта.
- Stock/guard replacement не оставляет под собой старый модуль, не меняет защищённый body/action и не проваливается в receiver. В AK12 cheek/regular stock и short/long handguard показываются взаимоисключающими сборками.
- Контроль посадок: magazine throat/body insertion; stock shoulder and hinge; handguard rear/front boundaries; side mount clear of controls; rail accessory sockets; muzzle collar, bore line and sight clearance. Сначала проверить Part/anchor transforms, затем module local offset; при конфликте записать только локальную предлагаемую коррекцию.

### GLB и runtime handoff

- На assetKey обязательны LOD0+LOD1, `UVMap`, finite vertices и корректные нормали; `blender_asset_audit.py` не должен находить missing metadata, collapsed UV triangles, degenerate triangles или invalid normals. Размеры GLB/atlas записать.
- Каждый модуль статичен; mesh не деформируется при action/bolt/reload. Прогнать обычные существующие first-person poses: idle, ADS, firing, reload swap/range, inspect; IK/grip targets и body/action не сдвигать.
- Не терять color/shadow/depth/ID-picking passes и `ModelAssets.finishPass()` метрики. Не считать neutral scene acceptance runtime acceptance. После интеграции нужны браузерные снимки оружейной/ADS, load errors=0 после warm load, без fallback+GLB двойника; фиксированная камера/LOD/вариант и замер draw calls, triangles, CPU-submit/RAF p50/p95 по существующему review recipe.
- Сравнивать FPS с `art/overhaul/baseline-browser-ak74m.json` и `baseline-browser-glock17.json`: baseline в контролируемом браузере около 60 Hz, CPU submit median ~2–2.5 ms, p95 ~2.8–3.4 ms; это только базовая точка одного браузерного стенда, не гарантия целевого GPU/performance. Не обещать «FPS не изменится» без реальных измерений.
- Фото и `sources.json` остаются private/reference-only и не входят в `public`, runtime atlas, GLB или release. В handoff перечислить оставшиеся visual gaps из AK QA ledger; PASSED не означает точную фабричную геометрию.

### Передача Sol → проверка Luna

Sol передаёт отдельный `.blend` source и GLB, таблицу ID/`assetKey`/slot/pivot/локальные поправки, counts LOD0/1, список материалов/текстур и хэши, ортографические виды (лево/право/верх/низ) плюс установленные preview для каждой уникальной формы. Luna проверяет: каждый ID против индивидуального approved brief и референс-пакета; уникальность варианта/вместимости; силуэт и стыки на защищённой базе; UV/PBR/LOD; отсутствие торговых marks; корректность локальной поправки и неприкосновенность body/action. Только после фактического runtime import и проверок renderer владельцем интеграции решение меняется на production-ready.
